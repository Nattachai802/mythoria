## Anti-Patterns Verdict

**LLM assessment**: ไม่มีกลิ่น AI slop หน้านี้เป็น master-detail ที่ตัดสินใจมาแล้วจริง ไม่ใช่ grid การ์ดสำเร็จรูป การเลือกแก้ไขแบบ inline แทนการเปิด modal เป็นการตัดสินใจที่ถูกตาม product register ("Modal as first thought is laziness") ความหนาแน่นเหมาะกับ power user ตาม PRODUCT.md ไม่มี gradient text, ไม่มี eyebrow, ไม่มี hero-metric, ไม่มี side-stripe เชิงตกแต่ง

จุดที่เข้าใกล้ ban: `border-l-2 border-l-primary` ที่รายการซึ่งถูกเลือก — แต่นี่คือ selection indicator ของ list item ไม่ใช่ accent ตกแต่งบนการ์ด ถือว่าใช้ถูกหน้าที่

**Deterministic scan**: `detect.mjs` บนไฟล์ทั้ง 7 ของ surface นี้ → **0 findings, exit 0**

**Visual overlays**: ไม่ได้ทำ — การ inject ต้องเปิด `live-server.mjs` ซึ่งผู้ใช้สั่งห้ามสตาร์ทเซิร์ฟเวอร์เองในเซสชันนี้ ใช้การวัดผ่าน JS บนแท็บที่ผู้ใช้รันอยู่แล้วแทน

**ข้อจำกัดของรอบนี้ที่ต้องบอกตรง ๆ**: เบราว์เซอร์ที่ผมเข้าถึงล็อกอินเป็นบัญชีเดโม จึงเปิดนิยาย `275aeebd…` (48 ไอเดีย) ไม่ได้ — เห็นแค่ 404 ที่ตรวจสภาพจริงได้คือนิยายเดโมซึ่งมี 0 ไอเดีย = เห็นเฉพาะ empty state ส่วนสภาพ "มีของ 48 อัน" วิเคราะห์จาก source + ภาพหน้าจอที่ผู้ใช้ส่งมา

## Overall Impression

หน้านี้ทำงานได้ดีในสิ่งที่มันตั้งใจ และการเปลี่ยนล่าสุด (ซ่อนไอเดียที่ถูกใช้แล้ว) แก้ปัญหาถูกจุด — จาก 48 บรรทัดที่เกือบทุกอันขึ้น "ใช้แล้ว" เหลือ 2 อันที่หยิบได้จริง นั่นคือความจริงที่ควรเห็น

แต่การเปลี่ยนนั้นสร้างสัญญาใหม่ที่ยังไม่มีใครอธิบาย: **ของหายไปได้เอง** ตอนนี้กฎนั้นถูกซ่อนอยู่ใน `title` tooltip ของปุ่มเดียว ซึ่งไม่ขึ้นบนมือถือ ไม่ขึ้นตอนโฟกัสด้วยคีย์บอร์ด และหายไปพร้อมกับหน้าว่างเมื่อมีข้อมูลจริง โอกาสที่ใหญ่ที่สุดคือทำให้ "ไอเดียไหลจากข้างนอก → รอ → ถูกใช้ → เข้าคลัง" มองเห็นได้ตลอดเวลา ไม่ใช่แค่ตอนหน้าว่าง

## What's Working

1. **Inline edit ในแพนขวา ไม่ใช่ modal** — แก้ชื่อ/เนื้อหา/หมวด/แท็กได้โดยไม่เสียบริบทของรายการทางซ้าย ตรงกับ product register และตรงกับ "Context without interruption" ใน PRODUCT.md
2. **ตัวกรองที่บอกจำนวนจริง** — chip หมวดแสดง count และซ่อนตัวเองเมื่อ count เป็น 0 บวกกับ "พบ X จาก Y" ตอนกรอง ผู้ใช้ไม่ต้องเดาว่ากรองแล้วเหลืออะไร
3. **ความหนาแน่นที่เหมาะกับงาน** — รายการซ้าย 240px แสดงชื่อ + สถานะ + แท็ก 2 อันในสองบรรทัด สแกน 20 รายการได้โดยไม่ต้องเลื่อน เหมาะกับนักเขียนที่มีไอเดียเป็นร้อย

## Priority Issues

### [P1] กฎสำคัญที่สุดของหน้าถูกซ่อนใน `title` tooltip

**Why it matters**: "ไอเดียจะหายจากรายการเมื่อถูกวางในฉาก" คือ mental model ใหม่ทั้งหมดของหน้านี้ native tooltip ไม่ขึ้นบน touch, ไม่ขึ้นเมื่อโฟกัสด้วยคีย์บอร์ด, หน่วงประมาณ 1 วินาที และปุ่มที่ถือ tooltip นี้จะไม่ปรากฏเลยถ้า `usedIdeas.length === 0` — แปลว่าผู้ใช้ใหม่ไม่มีทางรู้กฎนี้ก่อนที่มันจะเกิดขึ้นกับเขาครั้งแรก

**Fix**: ย้ายคำอธิบายออกจาก `title` มาเป็นข้อความที่มองเห็นได้ถาวรใต้แถบแท็บ (เช่น "ไอเดียที่วางในฉากแล้วจะย้ายไปกลุ่ม 'ใช้ไปแล้ว' อัตโนมัติ") หรือทำให้ตัวเลข "ใช้ไปแล้ว (46)" เป็นส่วนหนึ่งของ IA ถาวรแทนที่จะเป็นปุ่มที่โผล่มาแบบมีเงื่อนไข

**Suggested command**: `/impeccable clarify`

### [P1] แยกไม่ออกว่ากำลังอยู่โหมด "พร้อมใช้" หรือ "ใช้ไปแล้ว"

**Why it matters**: การสลับเปลี่ยนแค่ข้อความบนแท็บกับข้อความบนปุ่ม โครงหน้า สี และทุกอย่างที่เหลือเหมือนเดิมเป๊ะ ผู้ใช้ที่กดดูคลังเก่า แล้วสลับไปทำอย่างอื่น แล้วกลับมา จะเห็นรายการยาว ๆ และเข้าใจว่านั่นคือของที่พร้อมใช้ทั้งหมด — ซึ่งตรงข้ามกับความจริง นี่คือ mode error แบบคลาสสิก

**Fix**: ให้โหมดคลังมีสัญญาณคงที่ที่ไม่ใช่แค่ข้อความ เช่น พื้นหลังแพนที่ต่างออกไป แถบสถานะบนสุดของรายการ หรือทำเป็นแท็บที่สามจริง ๆ แทนปุ่มสลับ

**Suggested command**: `/impeccable layout`

### [P1] แพนซ้าย-ขวาไม่มี breakpoint — พังบนจอแคบ

**Why it matters**: คอนเทนเนอร์เป็น `flex` ที่มีรายการ `w-60 flex-shrink-0` (240px) และแพนรายละเอียด `flex-1` โดยไม่มี `md:` เลย ที่ viewport 375px หักด้วย `p-8` ของหน้า (64px) เหลือ ~311px → รายการกิน 240px แพนรายละเอียดเหลือ ~71px อ่านอะไรไม่ได้เลย และความสูงถูกล็อกไว้ที่ `560px` ตายตัว ไม่ยืดตามจอ

**Fix**: ต่ำกว่า `md` ให้ซ้อนกัน (แสดงรายการอย่างเดียว แตะแล้วค่อยเปิดรายละเอียดเต็มจอ) และเปลี่ยน 560px เป็นความสูงที่อิงกับ viewport

**Suggested command**: `/impeccable adapt`

### [P2] ปุ่มสลับอยู่ใน `role="tablist"` ทั้งที่ไม่ใช่แท็บ

**Why it matters**: `<Button>` ถูกวางเป็นลูกโดยตรงของ `TabsList` ของ Radix ซึ่ง render เป็น `role="tablist"` — spec ระบุว่าลูกของ tablist ต้องเป็น `role="tab"` screen reader จะประกาศโครงสร้างผิด และ roving focus ด้วยลูกศรของ Radix จะข้ามหรือสะดุดที่ปุ่มนี้ (ปัญหานี้เกิดจากการแก้ล่าสุด ไม่ใช่ของเดิม)

**Fix**: ย้ายปุ่มออกไปนอก `TabsList` วางในแถวเดียวกันด้วย flex container ที่ครอบทั้งสองอย่าง หรือทำให้มันเป็น `TabsTrigger` จริง ๆ

**Suggested command**: `/impeccable audit`

### [P2] `confirm()` ของเบราว์เซอร์ในแอปที่มี Dialog ของตัวเองอยู่แล้ว

**Why it matters**: การลบไอเดียเรียก `confirm()` ซึ่งเป็นกล่องของ OS — theme ไม่ได้ ฟอนต์ไทยไม่ตรงกับแอป ปุ่มเป็นภาษาระบบ และ block main thread โปรเจกต์นี้มี `Dialog`/`AlertDialog` ใช้อยู่ทั่วแอปแล้ว ความไม่สม่ำเสมอนี้ผู้ใช้รู้สึกได้ทันทีว่า "หลุด"

**Fix**: เปลี่ยนเป็น `AlertDialog` ชุดเดียวกับที่ `DeleteAllIdeasButton` ใช้ และเพิ่ม toast แบบมีปุ่ม "เลิกทำ" เพราะตอนนี้ลบแล้วกู้ไม่ได้เลย

**Suggested command**: `/impeccable harden`

**Casey (Mobile)**: แพนคู่ไม่ยุบบนมือถือ รายละเอียดเหลือความกว้าง ~71px · ปุ่มหลักทั้งหมด ("ไอเดียใหม่", "Sync Discord", แท็บ) อยู่บนสุดของหน้า นอกระยะนิ้วโป้ง · tap target วัดได้จริง 27–36px ต่ำกว่ามาตรฐาน 44px ทุกตัว

## Minor Observations

- สลับโหมดแล้วแพนขวาว่างทันที เพราะ `selectedIdea` หาจากรายการปัจจุบันเท่านั้น และ auto-select ทำงานแค่ตอน mount (`useEffect` dependency ว่าง) → ต้องคลิกเองทุกครั้งหลังสลับ
- `searchQuery` และ `categoryFilter` ไม่ถูกล้างตอนสลับโหมด ทำให้เห็น "ไม่พบไอเดียที่ตรงกัน" ในคลังที่มีของ 46 อัน ถ้าเผลอค้างคำค้นไว้
- ปุ่ม "ไอเดียใหม่" ปรากฏสองที่ด้วยน้ำหนักต่างกัน (หัวหน้า = primary ทึบ, ท้ายรายการ = outline เล็ก) ทั้งที่ทำสิ่งเดียวกัน
- คอนทราสต์โหมดสว่างผ่าน AA ทุกจุดที่วัดได้ (ต่ำสุด 4.66 ที่แท็บ inactive) โหมดมืดผ่านทุกจุดที่วัดได้บนพื้นทึบ (ต่ำสุด 6.26) — พื้นโปร่งใสวัดไม่ได้ด้วยวิธีนี้ ยังไม่ยืนยัน
- `Delete All` หายไปเองเมื่อไม่มีไอเดีย ดีแล้ว แต่ตอนนี้มันนับ `activeIdeasCount` จากไอเดียทั้งหมดรวมที่ใช้แล้ว — ผู้ใช้เห็น "พร้อมใช้ (2)" แต่กด Delete All แล้วลบ 48

## Questions to Consider

- ถ้า "ไอเดียที่ใช้แล้ว" ไม่ใช่ของที่ต้องซ่อน แต่เป็น**หลักฐานว่าระบบทำงาน** หน้านี้ควรแสดงมันเป็นความคืบหน้า (เช่น "ใช้ไปแล้ว 46 จาก 48") แทนที่จะเป็นปุ่มที่ต้องไปกดหาไหม
- ไอเดียที่ถูกใช้แล้วควรลิงก์กลับไปยังฉากที่มันไปอยู่ได้ไหม — ตอนนี้บอกแค่ว่า "อยู่ในฉากแล้ว" แต่ไม่บอกว่าฉากไหน ผู้ใช้ต้องไปไล่หาเอง
- ถ้าเป้าหมายคือ "ที่รับไอเดียจากข้างนอก" ทำไมการซิงค์ Discord ยังต้องกดเอง และทำไมมันถึงเป็นปุ่ม outline เล็ก ๆ ข้างปุ่มลบทั้งหมด
