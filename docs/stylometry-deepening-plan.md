# Stylometry Deepening — แผนยกระดับการวิเคราะห์ลีลาการเขียน (Patch 2.5)

> เป้าหมาย: เปลี่ยนการวิเคราะห์สไตล์จาก **"รูปนิ่ง 1 ใบต่อตอน"** (ตัวเลขสรุปหยาบ + ป้ายอารมณ์ heuristic)
> ให้เป็น **"วิดีโอ + ลายนิ้วมือ"** (เส้นโค้งตลอดตอน + โปรไฟล์เวกเตอร์ระดับงานวิจัย)
> ยังเป็น **statistical NLP ล้วน** (PyThaiNLP) — ไม่ใช้ LLM, deterministic, อธิบายได้

## ปัญหาของระบบปัจจุบัน

โมดูลปัจจุบัน ([`pythonservice/stylometry.py`](../pythonservice/stylometry.py), [`author_fingerprint_discovery.py`](../pythonservice/author_fingerprint_discovery.py)) ครอบ 4 มิติ — feature-rich แต่แต่ละมิติคือ **scalar เดียว/ตอน**:

| มิติ | ตอนนี้ | จุดอ่อน |
|------|--------|---------|
| ① Pacing & Mood | นับ `…!?` density → ป้ายอารมณ์ | หยาบ — pacing จริงอยู่ที่จังหวะประโยค ไม่ใช่จำนวนเครื่องหมาย |
| ② Author Voice | นับสรรพนาม (PPRS) | signal จิ๋ว — ลายเซ็นจริงอยู่ที่ function words ทั้งชุด |
| ③ Character Vibes | นับ particle จัดกลุ่ม | ดีแล้ว แต่หยุดที่นับ ไม่วัดระยะห่างระหว่างตัวละคร |
| ④ Lexical + Anatomy | **TTR** + avg ประโยค + ratio บทพูด | **TTR มีจุดบกพร่องเชิงวิธีการ** (ลดตามความยาวเสมอ) |
| Fingerprint | 5 features → z-score | เปราะ — ใช้ค่า macro แค่ 5 ตัว |

---

## การยกระดับ — รายมิติ

### ① Pacing → Sentence-Rhythm Curve
จังหวะเรื่องอยู่ที่ **ลีลาความสั้น-ยาวของประโยค** (action = สั้นรัว, บรรยาย = ยาวไหล) ไม่ใช่จำนวน `!`

- พล็อต **เส้นความยาวประโยคตลอดตอน** → "จังหวะหัวใจ" ของเรื่อง (tension curve จริง)
- เพิ่ม **variance / burstiness** (สั้น-สั้น-ยาว) เป็น metric
- จังหวะสลับ **บทพูด ↔ บรรยาย** (alternation rhythm)
- reuse `sent_tokenize` + `DialogExtractor.span` ที่มีอยู่แล้ว

### ② Author Voice → Function-Word Profile
ลายเซ็นนักเขียนซ่อนใน **คำเล็กที่ใช้โดยไม่รู้ตัว** (และ/ที่/ก็/นะ/แล้ว) — topic-independent, จับได้แม่นกว่าคำใหญ่
*(เปรียบเหมือนลายมือ — เขียนตัว "ก" ออกมาเองโดยไม่คิด)*

- สร้าง **function-word frequency vector** เต็มชุด (คำเชื่อม/บุพบท/ลักษณนาม/particle)
- เก็บเป็นโปรไฟล์ผู้แต่ง → ใช้เป็น input ของ Burrows's Delta (ดูส่วนสถาปัตยกรรม A)

### ③ Character Vibes → Inter-Character Distance
- ทำ **per-character particle fingerprint** เป็นเวกเตอร์
- วัด distance ระหว่างตัวละคร → ตัวละคร 2 คนที่พูดเหมือนกันเกินไป = "เสียงไม่แตกต่าง" (ปัญหาการเขียน)
- localize ตอนที่เสียงตัวละคร drift (ต่อยอด `track_character_voice` เดิม)

### ④ Lexical → MTLD / MATTR แทน TTR
**TTR ลดลงตามความยาวเสมอ** → เทียบตอนยาว-สั้นไม่แฟร์
*(เหมือนตัดสินว่าใครมีสีเยอะจากการนับสีในรูป — คนวาดรูปใหญ่ย่อมใช้สีซ้ำมากกว่า)*

- ใช้ **MATTR** (moving-average TTR, วัดเป็นช่วงแล้วเฉลี่ย) หรือ **MTLD** — ทนต่อความยาว
- เพิ่ม **hapax ratio** (คำที่โผล่ครั้งเดียว) + **ความยาวคำเฉลี่ย** (พยางค์ → register)

## การยกระดับ — สถาปัตยกรรม

### A. Burrows's Delta (แทน 5-feature z-score)
มาตรฐาน authorship attribution: z-score ของความถี่ function word ทั้งชุด + ระยะ Manhattan
- แข็งกว่า fingerprint ปัจจุบัน (5 ค่า macro) มาก
- ต่อยอด `AuthorFingerprint` — ขยาย `FEATURE_CONFIG` จาก 5 macro → function-word vector

### B. Rolling / Windowed Analysis — localize จุดเพี้ยน ⭐
ตอนนี้บอกได้แค่ "ตอนที่ 5 สไตล์หลุด" แต่ชี้ไม่ได้ว่าย่อหน้าไหน
*(เหมือนหมอบอก "ร่างกายผิดปกติ" แต่ชี้ไม่ได้ว่าเจ็บตรงไหน)*

- เลื่อน **sliding window** ในตอน วิเคราะห์ทีละช่วง
- ชี้ได้ระดับย่อหน้า: "ย่อหน้า 4-6 สไตล์ต่างจากรอบๆ" → จับ AI แทรก / ghostwriter ได้แม่น

### C. POS n-gram Profile
ลำดับชนิดคำ (คุณศัพท์-นาม-กริยา) จับ "ไวยากรณ์เชิงสไตล์" — adjective-heavy vs verb-heavy
- reuse `pos_tag` (perceptron/orchid) ที่มีอยู่

### D. Emotional Arc
- sentiment lexicon ไล่ตลอดตอน → เส้นอารมณ์จริง (แทน vibe จากเครื่องหมาย)
- **sensory-word density** (ภาพ/เสียง/สัมผัส) → วัด "showing" เชิงปริมาณ

## หลักการที่ยึด
- **statistical ล้วน ไม่ใช้ LLM** — สอดคล้องกับ stylometry เดิม (เร็ว, deterministic, โปร่งใส)
- **additive** — เพิ่ม field ใน JSONB ที่มีอยู่ ไม่ลบของเดิม ผลเก่ายัง render ได้
- **tuning ภาษาไทย** — function-word list, sensory lexicon, sentiment ต้องคัดสำหรับไทย

## นอก scope (รอบนี้)
- เปลี่ยนไป LLM-based style analysis
- cross-author attribution (เทียบกับนักเขียนคนอื่นนอกระบบ)
- real-time analysis ระหว่างพิมพ์ (คง manual/on-demand ตาม vision)

# Patch 3 — หน่วยที่วัด (2026-08-20)

> Patch 2.5 ทำฟีเจอร์เสร็จครบ แต่ไม่เคยตั้งคำถามว่า **หน่วยข้อความที่ป้อนเข้าไปใหญ่พอ
> ให้ตัวเลขมีความหมายไหม** — Patch 3 ตอบข้อนั้น ไม่ได้ลดบทบาทอะไร เพิ่มความน่าเชื่อถือ

## ที่มา

`sample-size` (Eder, *Does Size Matter?*, DH2010): ความถี่ของคำเป็นตัวแปรสุ่ม
ค่าประมาณจึงขึ้นกับขนาดกลุ่มตัวอย่าง ต่ำกว่าพื้นหนึ่ง คะแนนสไตล์ถูกครอบด้วย sampling noise
และ **ผลนี้ไม่ขึ้นกับอัลกอริทึม** — เส้นโค้งรูปเดียวกันทั้ง Delta, Delta Prime,
cluster analysis, MDS · เปลี่ยนไปใช้ตัวจำแนกที่ดีกว่าไม่ได้ทำให้ตัวอย่างขั้นต่ำสั้นลง

**ไม่ลอกเลขจากเปเปอร์** เพราะเกณฑ์จำนวนคำสมมติว่ามี word tokenization ซึ่งไทยไม่มี
จึงวัดจากคลังของเราเองแทน

## วัดจากคลังจริง (ECLIPSYS 40 ตอนที่มีเนื้อหา)

character 3-gram (ไม่ต้องตัดคำ) · เทียบระยะระหว่างหน้าต่างที่ **ติดกัน** (ควรคล้าย)
กับหน้าต่างที่ **อยู่ห่างกัน** (เพดานของความต่างที่มีจริง)

| ตอน/หน้าต่าง | คำ~ | ระยะติดกัน | sd | ระยะไกล | ติดกัน ÷ ไกล |
|---|---|---|---|---|---|
| 1 | 2,557 | 0.1686 | 0.0714 | 0.2326 | **0.72** |
| 2 | 5,115 | 0.1181 | 0.0420 | 0.1685 | 0.70 |
| 3 | 7,637 | 0.0936 | 0.0350 | 0.1433 | 0.65 |
| 4 | 10,230 | 0.0679 | 0.0279 | 0.1194 | 0.57 |
| 5 | 12,787 | 0.0513 | 0.0198 | 0.1066 | **0.48** |
| 6 | 15,350 | — | — | — | เหลือ 6 หน้าต่าง อ่านไม่ได้ |

ที่ 1 ตอน หน้าต่างติดกันต่างกัน **72%** ของความต่างระหว่างหน้าต่างคนละมุมเรื่อง —
"ตอนติดกัน" กับ "ตอนห่างกัน 20 ตอน" แทบแยกไม่ออก

**เส้นโค้งยังไม่แบนจนถึง 12,787 คำ** พื้นของคลังนี้จึง**สูงกว่า**เลขในเปเปอร์ (5,000–10,000)
สมมติฐาน (ยังไม่พิสูจน์): นิยายลงเป็นตอนมีทวนความ มีปมท้ายตอน โครงตอนจงใจต่างกัน
ความแปรปรวนระหว่างตอนจึงสูงกว่านิยายเล่มเดียวที่เขียนต่อเนื่อง

## ข้อค้นพบหลัก: พื้นไม่ได้กัดทุกฟีเจอร์

กัดเฉพาะของที่**ประมาณการกระจายจากคลังคำ** ไม่กัดของที่**นับสิ่งที่มีอยู่จริง**

| ฟีเจอร์ | n คืออะไร | กระทบ | หน่วยที่ควรใช้ |
|---|---|---|---|
| MTLD / MATTR | type ในคลังคำ | **หนัก** | หน้าต่าง 4–5 ตอน |
| Function-word profile + Burrows Δ | ความถี่ของคำชุดหนึ่ง | **หนัก** — ตรงกับที่ Eder วัด | หน้าต่าง 4–5 ตอน |
| POS n-gram | ความถี่ของแท็ก | หนัก + tagger ไทยไม่นิ่ง (ดู #5 ของ Patch 2.5) | หน้าต่าง 4–5 ตอน |
| Sentence-rhythm curve | จำนวนประโยค ~150/ตอน | **เบา** | รายตอน |
| Dialogue ratio / alternation | สัดส่วนของ span ที่นับได้ | **แทบไม่กระทบ** | รายตอน |
| Emotional arc / sensory density | จำนวนคำที่แมตช์ lexicon | ปานกลาง | รายตอน + แถบกว้าง |

## หน้าต่างสร้างยังไง — ต้องระบุ ไม่งั้นตัวเลขเทียบกับที่วัดไว้ไม่ได้

**แบบไม่ซ้อนกัน (tumbling)** ตอน 1–5, 6–10, 11–15 …

เส้นโค้งที่วัดไว้ข้างบนใช้แบบไม่ซ้อน ถ้าไปทำแบบเลื่อนซ้อน (1–5, 2–6, 3–7 …) หน้าต่าง
ที่ติดกันจะใช้ข้อความร่วมกัน 80% ระยะห่างจะดูต่ำกว่าความจริงมาก **ตัวเลขจะดูนิ่งขึ้น
ทั้งที่ไม่ได้นิ่งขึ้นจริง** และเทียบกับตารางข้างบนไม่ได้เลย

ตอนที่เหลือไม่ครบหน้าต่าง (เช่น 40 ตอน แบ่ง 5 เหลือ 0 พอดี แต่ 42 ตอนจะเหลือ 2)
**ไม่คำนวณ** ดีกว่าคำนวณจากหน้าต่างที่สั้นกว่าคนอื่น

## ที่เก็บผลระดับหน้าต่าง

`noteStylometry` ผูกกับ note ตัวเดียว แต่หน้าต่างครอบหลายตอน ใช้ตารางเดิมไม่ได้ตรง ๆ

ทางที่เบาที่สุด: เก็บใน `chapterStylometry` ที่มีอยู่แล้ว โดยนิยาม "หน่วย" ใหม่เป็นหน้าต่าง
พร้อมฟิลด์บอกว่าครอบ note ไหนบ้าง และ**ขนาดหน้าต่างที่ใช้ตอนคำนวณ** — ค่าจากหน้าต่าง
คนละขนาดเทียบกันไม่ได้ ถ้าไม่บันทึกไว้จะรู้ตัวตอนกราฟเพี้ยนแล้ว

## ข้อแลกที่ต้องรู้

**หน้าต่างใหญ่ = ค่าเชื่อได้มากขึ้น แต่จุดข้อมูลน้อยลง** — 40 ตอนแบ่งหน้าต่างละ 5 ตอน
เหลือ 8 จุด พอเห็นแนวโน้มทั้งเรื่อง ไม่พอทำระบบเตือนรายตอน

**ระบบเตือนรายตอนสำหรับฟีเจอร์กลุ่มบน ข้อมูลไม่รองรับ** ถ้าต้องการจริง ทางที่เหลือคือ
เปลี่ยน*สิ่งที่วัด* ไม่ใช่ขนาดหน้าต่าง — ไปวัดโครงสร้างจากกระดานพล็อต
(ดู [plot-analysis-plan.md](plot-analysis-plan.md)) ซึ่งไม่มีพื้นขนาดตัวอย่างมาบังคับ
เพราะนับของที่มีอยู่จริง ไม่ได้ประมาณจากการสุ่ม

## สิ่งที่การวัดนี้ยังไม่ได้พิสูจน์

- วัดด้วย character 3-gram ตัวแทนเดียว ไม่ใช่ฟีเจอร์จริงของไปป์ไลน์
  (เปเปอร์เคลมว่ารูปเส้นโค้งไม่ขึ้นกับอัลกอริทึม แต่นั่นคือคำเคลมของเปเปอร์ ไม่ใช่ผลของเรา)
- "ติดกัน vs ไกล" ปนกันระหว่าง sampling noise กับ drift จริงของผู้เขียนตลอด 40 ตอน
  แยกสองอย่างนี้ด้วยการวัดแบบนี้ไม่ได้
- Eder วัด **authorship attribution** (แยกว่าใครเขียน) ส่วนเราทำ **within-author drift**
