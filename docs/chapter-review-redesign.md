# รื้อระบบรีวิวรายตอน — stylometry + NarraBench

> สถานะ: ร่างออกแบบ ยังไม่ลงมือ
> อ้างอิง: [[NarraBench]] (Hamilton, Wilkens, Piper 2025, arXiv 2510.09869)

## ปัญหาของระบบปัจจุบัน

`app/api/novel/[novelId]/note/[noteId]/ai-review/route.ts` ยิง LLM 5 ครั้งด้วย
persona 5 แบบ แต่ทุกตัวได้ input เดียวกัน (`plainText.slice(0, 3000)` + RAG) และ
คืน output แบบเดียวกัน (ร้อยแก้ว 2-4 ประโยค) เก็บลง `aiChapterReviews`
เป็น `{persona, personaName, content}`

### 1. persona ต่างกันแค่น้ำเสียง ไม่ได้ต่างกันที่สิ่งที่ดู

ในระบบพิกัดของ NarraBench (Scale-Mode-Variance) ทั้ง 5 ตัวคือ
**Local · Holistic · Perspectival** เหมือนกันหมด → เรียก LLM 5 ครั้ง
ได้บทวิเคราะห์เดียวกัน 5 สำนวน ไม่ใช่ coverage 5 ด้าน

### 2. ถามคำถามระดับ Global ด้วยข้อมูลระดับ Local

ตารางที่ 1 ของเปเปอร์ให้รหัส SMV ไว้ชัด:

| aspect | รหัส | ต้องการ |
|---|---|---|
| plot, moral, conflict, archetype | **G**·H·P | ทั้งเรื่อง |
| plot arc | **G·P**·C | ทั้งเรื่อง + ลำดับ |
| duration, order | G·**P**·D | ลำดับหลายบท |
| suspense, curiosity, surprise | **G·P·P** | สภาวะผู้อ่านสะสมข้ามบท |
| interaction, dialogue, focalization, setting | **L**·D·D | บทเดียวพอ |

ระบบปัจจุบันมีข้อมูลพอสำหรับแถวล่างสุดแถวเดียว ที่เหลือคือการเดา

### 3. RAG ดึงจากอนาคต

`server/rag.ts` → `vectorSearch()` คัดด้วยความคล้ายอย่างเดียว
ไม่ได้กรองด้วย `notes.orderIndex` เลย ตัวกรองมีแค่ `it.id !== currentNoteId`

**ตอนรีวิวบท 5 จึงอาจได้เนื้อหาจากบท 20 มาด้วย** — AI รู้ตอนจบแล้ว
ประเมิน suspense/curiosity/surprise ไม่ได้เลยโดยหลักการ
และในทางกลับกันก็อาจไม่รู้ว่าบท 4 เพิ่งเกิดอะไร ถ้าเนื้อหาไม่คล้าย

> อาการที่ผู้ใช้รู้สึกว่า "AI ไม่เข้าใจตอนที่แล้ว" จริง ๆ แล้วคือ **ได้ข้อมูลผิดชุด**
> ไม่ใช่ข้อมูลไม่พอ

### 4. ทุกอย่างแสดงเป็น chat bubble เหมือนกัน

`components/project/ai-review-panel.tsx` เรนเดอร์ทุกความเห็นเป็นฟองแชท
นักเขียนแยกไม่ออกว่าอันไหน "ผิดต้องแก้" อันไหน "แค่รสนิยม"

## NarraBench ใช้ทำอะไรในที่นี้

**ไม่ได้เอา 50 aspects มาใส่ทั้งหมด** — ใช้รหัส SMV เป็น *ตัวจ่ายงาน*
ว่าคำถามไหนควรตอบด้วยอะไร:

| รหัส | ความหมาย | ผลต่อการออกแบบ |
|---|---|---|
| Variance = **D** | คำตอบตายตัว | ตัวเลข/กฎตอบได้ ไม่ต้องใช้ LLM |
| Variance = **P** | ขึ้นกับมุมมอง | ต้องใช้ LLM และควรแสดงเป็น "ความเห็น" |
| Mode = **P** | เป็นอนุกรมเวลา | ต้องมีข้อมูลข้ามบท |
| Scale = **G** | ระดับทั้งเรื่อง | ต้องสะสมสถานะ ไม่ใช่ตัดข้อความมาชิ้นเดียว |

> ข้อควรระวัง: NarraBench เป็นกรอบ *วัดว่า LLM เข้าใจเรื่องเล่าแค่ไหน*
> ไม่ใช่กรอบ *ให้ฟีดแบคนักเขียน* การหยิบมาใช้เป็น rubric เป็นการดัดแปลง
> ข้ามวัตถุประสงค์ — เปเปอร์ไม่ได้รับรองว่า aspect เหล่านี้เป็นฟีดแบคที่ดี
> ต่อการเขียน ให้คัดเฉพาะที่เป็นประโยชน์จริงกับนักเขียน

## ของที่มีอยู่แล้ว (สำคัญ — ไม่ต้องสร้างใหม่)

| มีอยู่ | ตอบ NarraBench feature ไหน |
|---|---|
| `noteStylometry` (JSONB รายบท: `pacingAndMood`, `chapterAnatomy`, `lexicalRichness`, `characterDialogueVibes`, `fingerprintAnalysis`) | Discourse/Time, Narration/Style, Narration/Perspective |
| stylometry route ดึงประวัติบทก่อนหน้าอยู่แล้ว (`historyData`) | ทำให้เทียบข้ามบทได้ทันที |
| `plotThreads` (`planted`/`developing`/`paid`/`abandoned`) + `plotThreadBeats` (`seed`/`reinforce`/`payoff`) | **Discourse/Revelation — curiosity** |
| Consistency Guardian | Story/Agent (deterministic) |
| `notes.orderIndex` | ลำดับการอ่าน — ใช้ตัดข้อมูลอนาคตออก |

**3 ใน 4 ของผลลัพธ์ที่ต้องการเป็น SQL ล้วน ไม่ต้องเรียก LLM**

## สิ่งที่นักเขียนจะเห็น

### (1) ตัวเลขเทียบบทก่อนหน้า — 📊 stylometry, ไม่ใช้ LLM

```
📉 จังหวะช้ากว่าค่าเฉลี่ย 5 บทก่อน 38%   (burstiness 0.21 → 0.13)
🗣️ บทพูด 12% — ต่ำสุดในเรื่อง
⚠️ เอริสกับไรกะพูดคล้ายกัน 87% แยกเสียงไม่ออก
```

มาจาก `noteStylometry` ของบทนี้เทียบกับ `historyData` — คำนวณล้วน

### (2) เส้นข้ามบท — 📊 stylometry

กราฟจาก `pacingAndMood` / `emotional_arc.curve` ของทุกบทเรียงตาม `orderIndex`
ทำให้เห็นช่วงที่แบนติดกัน

### (3) ปมค้าง — 🗄️ SQL ล้วน

```sql
-- thread ที่ยัง planted/developing และไม่มี beat role='payoff'
-- เรียงตามว่าหว่านไว้นานกี่บทแล้ว
```

```
🔴 "ใครฆ่าพ่อของเอริส" — หว่านบท 3, ผ่านมา 8 บท ยังไม่แตะ
🟡 "ดาบต้องสาป" — หว่านบท 6, ย้ำครั้งสุดท้ายบท 7
```

### (4) ความเห็นผู้อ่าน — 🤖 LLM (เหลือแค่ตรงนี้)

ป้อน **เฉพาะบท `orderIndex <= ปัจจุบัน`** เท่านั้น + สรุปสถานะสะสม
ผู้อ่านจำลองจึงรู้เท่าที่คนอ่านจริงรู้ ไม่มีสปอยล์จากอนาคต

```
"อ่านถึงตรงนี้ยังไม่รู้ว่าไรกะเป็นมิตรหรือศัตรู — ตั้งใจให้คลุมเครือหรือเปล่า?"
```

## เปลี่ยนอะไรบ้าง

1. **กรอง RAG ด้วยลำดับการอ่าน** — เพิ่มเงื่อนไข `orderIndex < current` ใน
   `server/rag.ts` (หรือรับ `maxOrderIndex` เป็นพารามิเตอร์) นี่คือการแก้ที่
   ให้ผลมากที่สุดต่อบรรทัดโค้ดที่แตะ และแก้ปัญหาสปอยล์ทันที
2. **ป้อน stylometry เข้า prompt** — ตอนนี้ route รีวิวไม่เคยเห็นตัวเลขเลย
   ทั้งที่มันนอนอยู่ใน `noteStylometry` ของบทเดียวกัน
3. **ลดจำนวน persona** — จาก 5 เหลือ 1-2 บทบาทที่ต่างกันด้วย *ขอบเขตที่รู้*
   ไม่ใช่ *นิสัย*: "ผู้อ่าน" (รู้ถึงบทนี้) กับ "บรรณาธิการ" (เห็นทั้งเรื่อง)
4. **แยกการแสดงผลตาม Variance** — deterministic ขึ้นเป็นข้อผิดพลาด,
   perspectival ขึ้นเป็นความเห็น
5. **ขยาย `aiChapterReviews`** — ปัจจุบันมีแค่ `{persona, personaName, content}`
   ต้องเก็บชนิด (metric / thread / opinion) และค่าที่อ้างอิงได้

## ทำตามลำดับไหน

| # | งาน | พึ่งพา | LLM |
|---|---|---|---|

`roadmap.md` ที่ว่า *statistical/deterministic ก่อน LLM*

## ที่ยังไม่รู้ / ต้องตัดสินใจ

- **ยังอยากได้ persona เชิงบุคลิกไหม** — เปเปอร์ชี้ว่า perspectival คือช่องที่
  benchmark ปัจจุบันขาด ดังนั้นแนวคิด persona ไม่ผิด แต่ควรใช้เฉพาะกับคำถามที่
  เป็น perspectival จริง ๆ ไม่ใช่ทุกคำถาม
- **"ปมค้างนานเกินไป" นับยังไงถึงเรียกว่านาน** — 5 บท? 10? หรืออิงสัดส่วน
  ความยาวเรื่อง ต้องลองกับเรื่องจริงก่อน
- **suspense curve จะวัดจากอะไร** — `emotional_arc` เป็น valence ไม่ใช่ tension
  โดยตรง อาจต้องหาตัวแทน (อัตราปมเปิด/ปิด + burstiness) หรือให้ LLM ให้คะแนน
  รายบทแล้วเก็บสะสม ยังไม่มีคำตอบ
- **บทที่ยังไม่เคยรัน stylometry** จะเทียบกับอะไร — ต้องมี fallback
